# Реестр биометрических метрик из ГОСТов

Единый справочник терминов и метрик биометрии (FMR, FNMR, FAR, FRR…), собранный из российских ГОСТов.
Для каждой метрики — дословная формулировка из каждого стандарта, где она есть, понятное описание для неспециалиста и формула.

**Смотреть реестр:** [Google Таблица](https://docs.google.com/spreadsheets/d/1FJ7YqoUL4OeHF_aONszUVQFVKlGMuOboZQGGx2sjFwk/edit?gid=1#gid=1) — обновляется сама; источник правды — этот репозиторий.

## Почему результатам можно доверять

Формулировки стандартов извлекает **программа, а не языковая модель**. Модель не пишет и не пересказывает текст ГОСТов —
она только помогает подключать новые документы и пишет пояснения в отдельном, помеченном слое. Каждый шаг проверяется автоматически.

| Что гарантируется | Как проверяется |
|---|---|
| Формулировки — дословно из PDF | Разбор делает детерминированный скрипт; любое изменение текста (склейка переноса, исправление распознавания) пишется в журнал |
| Исправления распознавания не выдуманы | Каждое исправление — в таблице конфига с основанием «что видно на скане страницы»; таблицу утверждает человек |
| Разбор правильный | **Эталон:** статьи каждого стандарта переписаны по изображениям страниц (не по распознанному тексту) и на каждом прогоне сверяются с разбором посимвольно |
| Новое не ломает старое | **Регрессия:** результат каждого стандарта побайтно сравнивается с утверждённой копией |
| Данные соответствуют структуре | **Схема:** каждое значение проходит ограничения своей колонки; тип, статус, область — только из справочников |
| Ничего не потеряно и не склеено | Нумерация статей без пропусков, в определении нет обрывков и чужих номеров, термины сверяются с алфавитным указателем стандарта, если он есть |
| Метрики разных стандартов сведены честно | Сливаются только записи с одинаковой аббревиатурой и областью; любое расхождение — флаг и строка в отчёте, ничего не сливается молча |
| Пояснения модели не оторваны от источника | Тексты модели лежат отдельно (`data/curated/`) с отпечатком формулировок: изменился стандарт — флаг `llm_stale`. Формулы проверяются подстановкой чисел: все части равенства должны совпасть |
| Статус «утвержден» — решение человека | Программа ставит только «черновик» и «отложено»; «утвержден» допускается только из файла, который правит человек |
| Результат повторяем | Два прогона дают побайтно одинаковые файлы |
| В таблицу не попадает непроверенное | Любое изменение идёт через pull request; автоматические проверки (CI) обязаны пройти до слияния, таблица публикуется только после них |

Когда подключается новый ГОСТ, модель сначала проводит разведку по сканам и **останавливается с вопросами**: колонка, ссылка на источник,
области, исправления распознавания. Ничего, что нельзя извлечь из документа, она не заполняет — ставит «—» и флаг.

## Как это работает

1. **PDF загружается** в `data/raw/`.
2. **Разбор:** текст очищается от колонтитулов и переносов, режется на статьи; из статьи берутся наименования, аббревиатуры, синонимы, определение.
3. **Классификация:** метрика или термин — по двум формальным признакам; область — по разделу стандарта.
4. **Проверки стандарта:** схема, эталон, нумерация, целостность → отчёт `data/out/<стандарт>/report.md`.
5. **Объединение:** одна метрика из нескольких стандартов — одна строка, формулировка каждого стандарта в своей колонке → `data/out/registry.csv`.
6. **Пояснения:** модель пишет описание и формулу для каждой метрики в `data/curated/`; они проходят ту же схему.
7. **Публикация:** после слияния в `main` и зелёных проверок реестр уходит в Google Таблицу.

## Как пользоваться

Всё делается на github.com, ничего не нужно запускать у себя.

- **Добавить ГОСТ:** загрузить PDF в `data/raw` (**Add file → Upload files**) → **Issues → New issue → «Добавить ГОСТ»**, вписать имя файла.
- **Сгенерировать пояснения для метрик:** задача «Сгенерировать тексты». **Проверить весь реестр:** задача «Проверить всё».
- **Отвечать агенту** — комментарием, начиная с `@claude`: сначала в задаче, после ссылки на PR — только в PR.
- **Принять результат:** в PR дождаться зелёной галочки проверок → **Merge pull request**. Таблица обновится сама.
- **Утвердить метрику:** открыть `data/curated/<id>.yaml` → карандаш → добавить `Статус: утвержден` → **Propose changes → Create pull request** → принять.
- **Скачать реестр:** `data/out/registry.csv` → **Download raw file**. Переопубликовать таблицу вручную: **Actions → CI → Run workflow**.

## Для разработчиков

```bash
python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python run.py          # полный прогон: стандарты, объединение, пояснения, README
.venv/bin/python -m pytest -q    # все проверки
```

- **Правила работы:** [`docs/RULES.md`](docs/RULES.md) — инструменты, согласованные решения, порядок проверок. Задания агенту — `prompts/add_gost.md`, `prompts/generate_fields.md`.
- **Структура реестра** — `config/registry_schema.yaml`; настройки стандарта — `config/<std_id>.yaml`; список стандартов — `config/merge.yaml`.
- **Отчёты:** `data/out/<std_id>/report.md` (стандарт), `data/out/merge_report.md` (объединение); утверждённые копии — `data/out/_baseline/`.
