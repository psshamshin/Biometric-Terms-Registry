# Реестр биометрических метрик из ГОСТов

Реестр терминов и метрик биометрии (FMR, FNMR, FAR, FRR и др.), сформированный на основе национальных стандартов.
Для каждой метрики приводятся дословные формулировки всех стандартов, в которых она определена, пояснение для неспециалиста и формула расчёта.

Актуальная версия реестра опубликована в [Google Таблице](https://docs.google.com/spreadsheets/d/1FJ7YqoUL4OeHF_aONszUVQFVKlGMuOboZQGGx2sjFwk/edit?gid=1#gid=1) (только для чтения).
Источником данных является данный репозиторий; таблица обновляется автоматически.

## Принцип работы

Формулировки стандартов извлекает детерминированная программа; языковая модель (агент) их не формирует и не изменяет.
Агент подключает новые документы под контролем владельца реестра и пишет пояснения в отдельном слое `data/curated/`.

1. **Разведка.** Агент читает PDF из `data/raw/`: текст, полосы сканов страниц, подозрения на ошибки распознавания.
   Черновик конфигурации даёт `python -m src.new_standard`.
2. **Вопросы владельцу.** Если решение не покрыто правилами (`docs/RULES.md`) и прецедентами (`docs/DECISIONS.md`) —
   область, исправления распознавания, спорный разбор, замена стандарта, — агент задаёт все вопросы одним комментарием и останавливается.
3. **Конфигурация и эталон.** После ответа агент пишет `config/<std_id>.yaml` с таблицей исправлений и эталон `tests/golden_<std_id>.yaml`:
   3–6 статей, переписанных по изображениям страниц.
4. **Разбор и проверки.** Программа разбирает стандарт и проверяет схему, эталон, нумерацию, полноту по указателю.
   Затем стандарт объединяется с реестром, строятся связи терминов (парные, дополнения, «используется в определении»).
5. **Пояснения.** По отдельной задаче агент пишет тексты метрик (краткое и подробное пояснение, формула); формулы проверяются подстановкой.
   Тексты терминов — только по явной просьбе.
6. **Проверка текстов.** По задаче «Проверить всё» формируется `data/out/validation_report.md`; ручная часть — `data/review/validation_review.yaml`.
7. **CI и принятие.** CI запускает `python run.py` и `pytest` (регрессия, повторяемость, актуальность `data/out/` и README).
   Владелец принимает pull request; публикация в Google Таблицу идёт только после успешного CI.

## Контроль достоверности

| Гарантия | Способ проверки |
|---|---|
| Формулировки соответствуют PDF | Разбор выполняет программа; каждая правка текста (склейка переноса, исправление распознавания) пишется в журнал очистки |
| Исправления распознавания обоснованы | Каждое — в конфиге со ссылкой на фрагмент скана; перечень утверждает владелец. Правка по «Изменению №…» — ключ `amendments`, флаг `amended` |
| Разбор корректен | **Эталон:** статьи, переписанные по сканам, сверяются с разбором посимвольно |
| Старые стандарты не затронуты | **Регрессия:** результат каждого стандарта побайтно сверяется с копией в `data/out/_baseline/` |
| Данные соответствуют структуре | **Схема:** значения проверяются по ограничениям колонки; тип, статус и область — из справочников |
| Статьи полны и не смешаны | Нумерация без пропусков, нет обрывов и чужих номеров, сверка с алфавитным указателем |
| Объединение прозрачно | Сливаются записи с одинаковой аббревиатурой и областью; расхождения — флаги и `merge_report.md` |
| Пояснения соответствуют источникам | Отпечаток источников в `data/curated/`; при изменении источников — флаг `llm_stale` |
| Утверждает человек | Программа ставит только «черновик» и «отложено»; «утвержден» — только из файла, изменённого владельцем |
| Результат воспроизводим | Повторный прогон даёт идентичные файлы |

Сведения, которых нет в документе, не заполняются: «—» и флаг.

## Порядок работы

Все операции — в веб-интерфейсе GitHub.

| Задача | Действия |
|---|---|
| Подключить стандарт | Загрузить PDF в `data/raw` (**Add file → Upload files**), создать задачу «Добавить ГОСТ» с именем файла |
| Пояснения | Задача «Сгенерировать тексты» |
| Проверить реестр | Задача «Проверить всё» |
| Ответить агенту | Комментарий с `@claude`: в задаче — до появления PR, далее — в PR |
| Принять изменения | Дождаться CI и нажать **Merge pull request** |
| Утвердить метрику | В `data/curated/<id>.yaml` добавить `Статус: утвержден` через PR |
| Получить реестр | `data/out/registry.csv`; повторная публикация — **Actions → CI → Run workflow** |

## Для разработчиков

```bash
python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python run.py          # стандарты, объединение, пояснения, проверка текстов, README
.venv/bin/python -m pytest -q    # все проверки
```

- Правила: [`docs/RULES.md`](docs/RULES.md); решения: [`docs/DECISIONS.md`](docs/DECISIONS.md); задания агенту: `prompts/`.
- Структура реестра: `config/registry_schema.yaml`; стандарты: `config/<std_id>.yaml`; перечень: `config/merge.yaml`.
- Отчёты: `data/out/<std_id>/report.md`, `data/out/merge_report.md`, `data/out/validation_report.md`.
