# CLAUDE.md

## Проект

Детерминированный парсер ГОСТов по биометрии: из PDF в `data/raw/` собирает реестр терминов и метрик по каждому стандарту
и общий реестр (`data/out/`). Структура реестра — `config/registry_schema.yaml`, стандарты — `config/<std_id>.yaml`,
список подключённых и `priority` — `config/merge.yaml`. Тексты LLM и статусы человека — слой `data/curated/`.

## Где правила

**Перед любым действием прочитай `docs/RULES.md`** — согласованные решения, инструменты, порядок разведки, правила конфига,
исправлений, эталона и регрессии. Опирайся на него, а не на память; при расхождении с задачей — спроси.

Задачи выполняются строго по промптам:
- `prompts/add_gost.md` — подключение нового ГОСТа и проверка всего реестра (раздел «Главные правила» обязателен всегда);
- `prompts/generate_fields.md` — тексты для метрик (колонки 13, 14, 16) и терминов (колонки 13, 14), строго по списку
  `python -m src.curated pending`; контекст записи — только `python -m src.curated context <id>`;
  направление «лучше» («Ниже/Выше — лучше») в текстах не указывается;
- `prompts/validate_fields.md` — проверка текстов, отчёт `data/out/validation_report.md`, ручная часть — `data/review/validation_review.yaml`.

Журнал решений — `docs/DECISIONS.md`: читай перед подключением нового стандарта, действуй по прецедентам, новые решения дописывай туда же.
Черновик конфига нового стандарта — `python -m src.new_standard data/raw/NNNNN.pdf` (конфиги подключённых стандартов не трогай).
Рост правил: новый вариант оформления — новый ключ конфига с тестом на статью-пример; поведение существующих ключей не меняется;
больше трёх новых ключей — остановись и спроси; в сводку — сколько ключей использовано и сколько добавлено.

Останавливайся и спрашивай только по критериям раздела «Что решать самому и когда останавливаться» в `prompts/add_gost.md`
(схема — колонки, справочники, признаки метрики, правила пар и объединения; ограничения формата полей расширяй сам по `docs/RULES.md`; замена подключённого стандарта, изменение выхода подключённых, неоднозначный скан, решение вне правил и прецедентов).
Остальное решай сам и записывай в сводку, в раздел «Решения, принятые самостоятельно».
На остановке задай все вопросы **одним комментарием**, каждый — с рекомендуемым вариантом, и закончи работу. Ответ придёт следующим комментарием.

## Как работать в GitHub

- Никогда не коммить в `main`. Работа — в ветке, которую создаёт запуск, и в PR.
- **Задача (issue):** шаг 0 и вопросы — комментарием в задаче. Когда сделаешь первые коммиты, дай ссылку на создание PR
  и попроси Павла открыть PR по ней; дальше вся работа — только в PR (там коммиты идут в ветку PR).
- **Если ответ пришёл в задаче, а ссылку на PR ты в этой задаче уже давал** — не начинай работу заново в новой ветке:
  попроси перенести ответ в PR (или открыть PR по ссылке, если он ещё не открыт) и закончи.
- Перед тем как сказать «готово»: `python run.py` и `python -m pytest -q`; результат (сводка и число тестов) — в комментарии.
- Выход в `data/out/` и разделы README между маркерами `<!-- AUTO:… -->` руками не правь — только через `python run.py`.
  Результат прогона (`data/out/`, `README.md`) коммить вместе с изменениями — иначе CI упадёт на проверке актуальности.
- Тексты LLM и статусы — только через `data/curated/<id>.yaml`. Заготовка и отпечаток:
  `python -m src.curated template <id>`, `python -m src.curated fingerprint <id>`.
  Отпечаток — только по заполненным колонкам источников; при подключении стандарта руками его не правь (`llm_stale` — ожидаемо).
- Внешних сервисов нет; Miro не используется.

## Команды

```bash
python run.py                          # все стандарты, объединение, слой curated, разделы README
python run.py config/<std_id>.yaml     # один стандарт → data/out/<std_id>/
python -m pytest -q                    # все проверки, включая регрессию по data/out/_baseline/
python -m src.recon text|scan|mixed …  # разведка PDF: текст, полосы скана, ошибки распознавания
python -m src.new_standard data/raw/NNNNN.pdf  # черновик конфига нового стандарта + сводка
python -m src.curated pending [std_id] # записи (метрики и термины), которым нужны тексты
python -m src.curated context <id>     # замкнутый пакет записи для генерации и проверки
python -m src.baseline compare|update  # сверка с базовыми копиями («всё, кроме колонки») и их обновление
```
